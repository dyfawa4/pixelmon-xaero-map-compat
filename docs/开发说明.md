# 开发与构建

## 转换核心与界面

Python 3.12 标准库即可运行转换测试：

```powershell
python -X utf8 tests/test_migration.py
python -X utf8 migration/地图坐标迁移.py
```

界面需要 Python 的 Tk 支持；坐标转换不依赖 Java。通过源码运行时，组件生成入口还需要下述适配资源包。

## 重建 Windows 便携工具

在 Windows、带 Tk 的 Python 3.12 中运行：

```powershell
python -X utf8 tools/build_migration.py
```

构建脚本把 PyInstaller 6.16.0 放入项目自身 `.cache`，不向系统 Python 全局安装依赖。普通源码检出没有本机原生构建产物时，会根据 `config/payload.lock.json` 下载并校验本项目 Release 的 `adapter-payload-v0.1.0.zip`。

这个资源包包含本项目编译好的原创适配类、原创 ASM 修改器、BSD 许可的 ASM 9.6 及清单；不包含原版 Xaero／Minecraft／Pixelmon 类。此路径是复用已验收适配资源来重建桌面工具，不代表从源码重新编译了地图适配逻辑。

需要在无网络环境下准备界面资源时，将下载的适配资源包放到本机，然后通过 `tools/payload_bundle.py` 的 `restore(archive, destination, expected_sha256)` 按锁定哈希恢复到 `.cache/installer-payload`。

生成器的原文件固定在 `config/upstream.json`，只接受匹配版本和 SHA-256 的三个官方输入。资源包清单也记录每一个内嵌文件的 SHA-256。

## 从 Java 源码重建适配组件

这一路径需要开发者自行准备 JDK 11，以及 Minecraft 1.16.5／Forge 36.2.42 的 SRG 编译 API、Pixelmon 本体 API 和 ASM 9.6；这些第三方编译依赖不放进仓库。原版三个地图 JAR 放入 `deps/`，文件名和哈希见 `config/upstream.json`。

准备一个本地 JSON 文件，`classpath` 是用分号分隔的编译依赖 JAR 绝对路径：

```json
{"classpath":"C:/dev/apis/minecraft-srg.jar;C:/dev/apis/forge-api.jar;C:/dev/apis/Pixelmon-1.16.5.jar;C:/dev/apis/asm-9.6.jar;C:/dev/apis/asm-tree-9.6.jar;其他所需依赖"}
```

然后运行：

```powershell
python -X utf8 tools/build.py --jdk "C:/Program Files/Java/jdk-11" --base-build "C:/dev/map-classpath.json"
python -X utf8 tools/prepare_installer.py
python -X utf8 tools/build_migration.py
```

首次原生编译会把依赖复制到本项目 `deps/build` 并保存哈希；后续使用固定副本。原生构建会输出两个地图 JAR 和 `dist/build-receipt.json`。有此清单时，`prepare_installer.py` 使用当前本地构建生成资源，不下载预编译适配资源包。

旧电脑上的默认引导路径仅为本地维护便利；其他开发者应显式指定 `--base-build`。需要修改编译依赖集时，请使用新的检出目录或明确维护自己的本地固定依赖清单。

## 验证边界

CI 仅运行不依赖游戏的坐标迁移测试。原生字节码／Forge 核心转换验证和完整整合包实机验收需要本地游戏依赖，不能把 CI 绿色解释为所有物种、服务器、显卡及版本均已测试。验收范围见 [验证记录](验证记录.md)。

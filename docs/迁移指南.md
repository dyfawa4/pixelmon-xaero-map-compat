# 从旅行地图迁移到宝可梦定制 Xaero

本指南面向普通玩家。**当前版本迁移坐标点和历史死亡点，不迁移已探索地形。** 原旅行地图目录保留，切换后 Xaero 的地形会按自身机制绘制。不要删除旧 `journeymap` 文件夹。

## 一、先确认你的游戏实例目录

实例目录是实际存放 `mods`、`config`、`saves` 等文件夹的位置，不一定是启动器所在目录。

- 普通实例可能在 `.minecraft`。
- 开启版本隔离后，通常在 `.minecraft/versions/你的整合包版本`。
- 在 PCL、HMCL 等启动器中打开对应版本的“游戏文件夹”，可以直接找到它。
- 不需要服务器管理员协助；工具读取的是玩家自己电脑上保存的旅行地图坐标点。

来源和目标可以是同一个实例，也可以是两个不同的实例。先备份旧实例的 `journeymap` 目录，以及已存在的 `xaero` 目录。

```mermaid
flowchart LR
  A[找到旧实例] --> B[保留 journeymap 备份]
  B --> C[生成并安装三个地图组件]
  C --> D[进入目标世界一次并退出]
  D --> E[选择来源和目标]
  E --> F[预览并导入坐标点]
  F --> G[游戏内核对]
```

## 二、安装定制地图

### 离线完整包：直接安装

如果下载的是文件名含“离线完整包”的版本，包内 `mods/` 已有生成好的三个地图组件，**无需运行生成器，也无需联网**。

完全退出游戏，备份原地图组件和数据，将包内 `mods/` 的三个 JAR 复制到目标实例 `mods/`。移走旧 Xaero 小地图、世界地图、重复的 XaeroLib 和 JourneyMap JAR，保留 Pixelmon 本体、回迁模组及整个 `journeymap` 数据目录。启动并进入对应存档或服务器一次，再退出游戏，然后直接从本指南“三”开始迁移坐标点。

离线包内的 `地图坐标迁移.exe` 自带转换器运行环境，不需要 Python，不会为坐标转换访问网络。它附带的“生成地图组件”功能仅供重新生成组件时使用。

### 只有工具包：生成后安装

1. 从本项目 Releases 下载分享包，解压后双击 `地图坐标迁移.exe`。无需安装 Python。
2. 点击主窗口右上方“安装 / 生成宝可梦地图组件…”。
3. Java 程序一般会自动识别。未识别时选择 Java 11 或以上版本的 `bin/java.exe`。这是生成器使用的 Java；Minecraft 1.16.5 这套整合包建议继续使用已经验证的 Java 11。
4. 选择一个独立输出文件夹，例如 `下载/宝可梦地图组件`，不要直接选择游戏 `mods`。
5. “已有官方原版”可以留空，生成器会下载固定版本的作者官方 Modrinth 文件，校验 SHA-256 后生成组件。下载受网络影响时，也可以自行获取以下原文件，将它们放到同一个文件夹，再选中这个文件夹离线生成。

| 必须配套的原文件 | 版本 |
| --- | --- |
| `xaerominimap-forge-1.16.5-26.6.0.jar` | 小地图 26.6.0 |
| `xaeroworldmap-forge-1.16.5-1.47.0.jar` | 世界地图 1.47.0 |
| `xaerolib-forge-1.16.5-1.7.3.jar` | 共享依赖 1.7.3 |

6. 点击“生成地图组件”，等待完成。输出目录会出现两个文件名含 `pixelmon-0.1.0-dev3` 的定制地图 JAR、一个 XaeroLib JAR，以及生成清单。
7. **完全退出游戏。** 将这三个 JAR 复制到目标实例 `mods`。移走原来的 Xaero 小地图、世界地图、重复的 XaeroLib，以及 JourneyMap JAR。保留 Pixelmon 本体和需要的重铸内容回迁；只停用 JourneyMap 模组文件，保留 `journeymap` 数据目录。
8. 启动游戏，进入准备迁入的单人存档或多人服务器一次，正常退出游戏。此时才会有正确的 Xaero 目标目录。

公开包在玩家本地生成定制组件，最终仍是魔改后的原生大小地图，不需要额外装一个兼容模组。原作者：Xaero96；官方入口：[小地图](https://modrinth.com/mod/xaeros-minimap)、[世界地图](https://modrinth.com/mod/xaeros-world-map)、[XaeroLib](https://modrinth.com/mod/xaerolib)。

## 三、找到旅行地图来源

在工具主窗口，“旅行地图所在目录”选择旧实例目录，点击“扫描”。下拉框会列出单人世界和多人服务器，选择你自己的对应项。

目录通常长这样：

```text
旧实例/
  journeymap/data/
    sp/单人世界名称/waypoints/*.json
    mp/服务器名称/waypoints/*.json
```

也可以直接选择 `sp/单人世界名称`、`mp/服务器名称`，或者其中的 `waypoints` 文件夹。不要选择某一个 JSON 文件，也不要把多个不同服务器的 JSON 混进同一个来源目录。

若没有扫描到来源，检查选择的是否为实际启用版本隔离的实例，以及来源中是否确实存在 `waypoints/*.json`。只有地形 PNG、没有坐标 JSON 的目录无法凭空恢复坐标点。

## 四、选择对应的 Xaero 目标

在“Xaero 所在目录”选择目标游戏实例，点击“扫描”，从下拉框选择对应存档或服务器。

```text
目标实例/
  xaero/minimap/存档或服务器标识/
    config.txt
    dim%0/waypoints.txt                       主世界
    dim%-1/waypoints.txt                      下界
    dim%1/waypoints.txt                       末地
    dim%pixelmon$ultra_space/waypoints.txt     究极空间
```

工具不会根据相似名称擅自判断两个服务器相同。旧服务器改过地址或端口、世界改过名时，也要由你明确选择正确目标。

目标列表为空时，先检查 `xaero/minimap` 是否存在；用本定制版进入该存档或服务器一次后退出，再扫描。旧版 `XaeroWaypoints` 目录不作为本工具的直接写入目标。

## 五、核对维度并预览

1. 查看“维度对应”。工具读取 JSON 的 `dimensions`，主世界、下界、末地和究极空间分别存放，不进行下界八倍坐标缩放。
2. 服务器有多个子世界时，目标下拉框会出现多个路径。必须明确选中对应子世界；不确定时先进入服务器的目标世界创建一个命名清晰的测试点，退出后根据该文件定位，再转换。可选择“不导入此维度”。
3. 默认勾选“包含历史死亡点”，可以取消。
4. 点击“生成预览”，逐项核对名称、坐标、维度和显示状态。

| 预览结果 | 含义 |
| --- | --- |
| 新增 | 将追加到目标默认路径点分组 |
| 已存在 | 同名、同坐标、同类型已存在，不再追加 |
| 不导入 | 你关闭了该维度或死亡点导入 |
| 异常源文件 | 内容缺失/格式错误，跳过并列入报告 |

同一 JSON 对应多个维度时，会分别生成对应维度的点，预览数量可能多于 JSON 文件数。不同名称但同坐标的点会分别保留。颜色会选择 Xaero 原生色板中最接近的一项；自定义 JourneyMap 图标不转换。

## 六、正式导入与游戏内检查

1. 确认目标游戏已经完全退出，勾选“我已完全退出目标游戏”。
2. 点击“导入坐标点”。工具先保存备份，再写入；原文件已有点位、分组和注释保留。原旅行地图数据不写入、不删除。
3. 启动目标实例，进入对应世界，打开 Xaero 路径点列表。默认通常为 `U`，以你实际按键设置为准。
4. 查看默认路径点分组 `gui.xaero_default`，核对熟悉的家、商店、传送点等名称和坐标。大小地图共用这些路径点。
5. 原来关闭的点仍是关闭状态，不会突然全部显示；死亡点以“历史死亡点”导入。
6. 主世界和究极空间分开保存。进入对应维度，或在 Xaero 列表中选择对应维度/子世界，才能看到相应点位。
7. 如需验证去重，完全退出游戏，再对相同来源生成预览。未修改点位的情况下，新增应为 `0`。

如果列表里有点但地图不显示，检查点位的启用状态、路径点分组、维度/子世界选择及 Xaero 的显示距离/显示设置；这不表示坐标已丢失。部分服务器也可能限制地图功能。

## 七、备份、撤销和回退

每次实际导入都会在目标实例生成独立目录：

```text
xaero-migration-backups/日期-编号/
  manifest.json    来源与目标哈希、迁移预览、写入状态
  before/          迁移前的原文件（原本不存在的文件没有该副本）
  after/           本次导入后的文件
```

需要撤销：完全退出游戏 → 工具中勾选退出确认 → 点击“恢复迁移前备份…” → 选中含 `manifest.json` 的那一层目录 → 核对目标并恢复。

如果迁移后又新增、修改过点位，工具会拒绝整体恢复，避免抹掉新记录。这时原文件仍在备份 `before` 中，可单独取出人工合并。预览之后来源或目标发生变化时，也会要求重新预览。

回退到旅行地图：退出游戏，恢复原地图 JAR，停用定制 Xaero 组件；原 `journeymap` 目录一直保留。若需要恢复原 Xaero 点位，使用迁移备份。工具不修改 Minecraft 存档中的方块、实体或背包。

## 八、回迁自制宝可梦

地图直接读取 Pixelmon 实体实际返回的精灵图，同一物种的普通/异色/形态按实际贴图区分，不维护固定全国编号图片表。回迁自制小智皮卡丘 `CapPikachu`（编号 1026）属于覆盖范围，普通/异色有专项验证；回迁桃歹郎等新增物种也已纳入此前图标检查。

后续新增物种只要仍使用 Pixelmon 宝可梦实体，并正确提供可访问的精灵图，就能沿用该入口。新物种本身缺图、资源路径错误，或改成不同实体类型时，不应把未测试情况描述为自动保证可用。雷达范围仍受客户端同步与服务器规则约束。

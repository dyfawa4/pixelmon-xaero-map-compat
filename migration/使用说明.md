# 旅行地图 → Xaero 坐标点迁移工具 1.0.0

双击 `地图坐标迁移.exe` 即可使用，不需要安装 Python、Java 或额外模组。工具离线运行，支持中文路径。

离线完整包已带 `mods/` 三个成品地图组件，直接安装它们即可，坐标转换不需要联网。工具右上方“安装 / 生成宝可梦地图组件…”是可选的重新生成入口：该入口需要 Java 11+，选择本地官方原版目录时离线处理，留空时联网下载；不影响坐标转换功能离线使用。完整教程见包内 `迁移指南.md`。

## 使用步骤

1. 用本项目的 Xaero 定制版进入要迁入的存档或服务器一次，然后完全退出游戏。
2. 打开工具，选择旅行地图所在的游戏实例目录，点击“扫描”，选中自己的世界或服务器。也可以直接选 `journeymap/data/sp/世界名`、`journeymap/data/mp/服务器名`，或其中的 `waypoints` 文件夹。
3. 选择 Xaero 所在的游戏实例目录并扫描，选择对应的目标世界或服务器。来源和目标可以位于不同实例。
4. 检查维度对应。主世界、下界、末地、究极空间自动分开；服务器存在多个子世界时，必须手动选择正确目标文件。不要将不同服务器的数据混在一起。
5. 点击“生成预览”，核对名称、坐标、维度和数量。异常 JSON 会列出并跳过，可导出完整报告。
6. 勾选“我已完全退出目标游戏”，点击“导入坐标点”。完成后启动游戏，在 Xaero 默认路径点分组查看。大小地图共用这些点位。

## 保留内容

- 中文/英文名称、X/Y/Z 坐标、原启用/关闭状态、维度归属。
- 原 RGB 颜色选择 Xaero 原生色板中最接近的颜色。
- 死亡点作为 Xaero 历史死亡点导入，避免将每一个旧死亡点设为当前导航目标。
- 跨多个维度的同一 JourneyMap 点会分别出现在对应维度。
- 目标原有路径点、分组和文件注释保留；新增点加入默认分组。
- 按名称、坐标和死亡点类型去重，重复导入不会不断生成相同点位。不同名称但相同坐标的点仍分别保留。

Xaero 使用特殊标记存储冒号，工具按其原生规则转换。换行和控制字符会转成空格；极少见的名称中原有连续两个 `§` 会分开，避免被原生读取器误解。原名称可从源 JSON 查回。

## 备份与恢复

每次写入前，工具在目标游戏实例的 `xaero-migration-backups/日期-编号/` 中保存原文件、导入后的文件和带 SHA-256 的清单。写入失败时自动回滚已写入的文件。

需要撤销时，完全退出游戏，在工具中点击“恢复迁移前备份”，选中含 `manifest.json` 的单次备份目录。若迁移后又新增、编辑过点位，工具会拒绝整体恢复，避免抹掉新点位；可从备份 `before/` 目录取回原始文件并人工合并。不要随意编辑备份清单。

预览后若来源或目标文件变化，工具会停止导入并要求重新预览。检测到对应地图被游戏占用时也会停止。

## 当前范围

适配 JourneyMap 5.8.6 的单点 JSON，以及本项目 Xaero 小地图 26.6.0 / 世界地图 1.47.0 的 `xaero/minimap/世界/维度/waypoints.txt` 格式。旧版 `XaeroWaypoints` 目录不作为直接写入目标。

本版优先迁移坐标点，**不转换已探索地形**。两种地图的缓存结构及地下层表达不同，目前没有通过完整可靠性验收的转换；旅行地图原目录不会修改，地形图片与缓存仍在原处。切换模组前请保留整个 `journeymap` 目录。

地图图标、自定义 JourneyMap 图标、精确 RGB、地形高度/生物群系数据及 JourneyMap 专有设置不属于本版转换范围。

## 开发者

`migrate_core.py` 是无第三方依赖的转换核心，`地图坐标迁移.py` 是 Tk 中文界面，`../tools/build_migration.py` 构建 Windows 便携版；测试在 `../tests/test_migration.py`。

源码 CLI 默认只预览，显式 `--apply` 才写入：

```powershell
python -X utf8 地图坐标迁移.py --source "实例/journeymap/data/sp/世界" --target "实例/xaero/minimap/世界" --report "报告.json"
```
